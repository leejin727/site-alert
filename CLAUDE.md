# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A university notice alert system (target: Myongji University boards, `mju.ac.kr`). It polls board RSS feeds, stores new posts, and is being built toward push notifications plus Gemini-based analysis of each notice (summary, category, deadlines, apply method, target). Work is staged ("1단계", "3단계", "5단계", "7단계" in comments); comments marking a future stage show where that stage will plug in (e.g. the `logger.info("[새 글]...")` line in `scheduler.py` becomes push sending).

명지대 공지를 수집해 AI로 정리하고, 학생의 할 일과 일정으로 바꿔주는 서비스. 앱은 Android 우선, 추후 웹·iOS.

All code comments, log/CLI messages, and API error messages are in Korean — keep that convention.

## 코딩 규칙
- 주석은 꼭 필요한 곳에만. 코드를 그대로 번역하는 주석은 쓰지 않는다.
- 기존 파일 구조와 네이밍을 따른다. 새 패턴을 임의로 도입하지 않는다.
- 외부 라이브러리를 추가하기 전에 먼저 물어본다.
- 큰 변경은 구현 전에 계획을 먼저 보여준다.

## AI 추출 원칙 (중요)
- Gemini가 공지에서 뽑은 값은 반드시 근거 문장과 함께 저장한다. (`NoticeAnalysis`의 `*_evidence` 필드)
- 입력에 없는 값은 추론해서 채우지 않고 null + unclear로 처리한다. (현재 코드에서는 값을 null 또는 `"불명확"`으로 두고, `resolve_analysis`가 그런 필드를 모아 `unclear`에 저장)
- 공지에 적힌 날짜를 읽는 것은 Gemini가 한다. 단 결과는 반드시
  ISO 형식(YYYY-MM-DD)과 근거 문장을 함께 반환한다.
  (현재: 원문에 연도가 없을 수 있어 Gemini는 적힌 그대로 year·month·day로 옮기고, 연도 보정과 ISO 날짜 확정은 저장 직전에 코드가 한다)
- 읽어낸 날짜로 하는 계산(역산 배치, D-day, 정렬)은 코드가 한다.
  Gemini에게 날짜 연산을 시키지 않는다.

## Layout

- `check.py` + `seen.json` — stage 1 standalone prototype (RSS diff against a JSON state file). Superseded by `serve/`; `check/` is its virtualenv.
- `serve/` — the real backend (FastAPI + SQLModel + PostgreSQL + APScheduler). Dependencies are installed in the system `python3` (3.14); `serve/.venv` exists but is missing them. It is a package (`serve/__init__.py`): always use `serve.`-prefixed imports and run with `-m` from `notice/`; `python3 serve/x.py` or bare `from db import` will fail. `alembic.ini` sets `prepend_sys_path = %(here)s/..` so Alembic finds the package from any folder. Script outputs and prompt files are located via `Path(__file__)`, not the working directory.
- `site_alert/` — Flutter client (Android first). `lib/api.dart` (`ApiClient`, `http` package; base URL from `--dart-define=API_BASE_URL`, else `ApiClient.defaultBaseUrl()` picks `http://10.0.2.2:8000` on Android (the Mac's localhost from the emulator) and `http://127.0.0.1:8000` elsewhere (iOS simulator, web, desktop); decodes `bodyBytes` as UTF-8 for Korean), `lib/models.dart`, `lib/main.dart` (`HomeShell`: bottom `NavigationBar` with "공지" / "내 할 일"; switching tabs rebuilds the screen so it reloads), `lib/screens/my_tasks_screen.dart` (`GET /tasks`; undone tasks first, "완료 N개" section below; D-day computed on the device by `daysLeft`, D-3..D-day (`urgentDays`) highlighted with the error color via `InfoChip(urgent:)`; an undone task whose deadline has passed gets a grey, struck-through title; `scheduled_date` shown as a chip ("오늘 하기", "11/15에 하기"); checkbox is optimistic → `PATCH is_done`, reverted on failure; tap opens the notice's preview; AppBar "이번 주 회고" opens `weekly_review_screen.dart`), `lib/screens/weekly_review_screen.dart` (`GET /reviews/weekly`: "N개 중 M개 완료 · P%" + progress bar, read-only list of unfinished tasks, memo field → `PUT`; ← → moves by week, but not past the current week, which is taken from the first server response; leaving a week with an unsaved memo asks for confirmation), `lib/screens/notice_list_screen.dart` (notice cards with the "이거 할래" button; disabled "분석 중" for unanalyzed notices) and `lib/screens/task_preview_screen.dart` (calls `POST /notices/{id}/tasks` on open — loading view while Gemini runs, error + "다시 시도"; unclear warning banner, deadlines/apply method with evidence, tap a task → bottom sheet → `PATCH`, add/delete, "원문 보기" via `url_launcher` always pinned at the bottom, "저장" → `POST …/tasks/confirm` then pops `true`; backing out leaves drafts and the card unchanged). Web: `contentInset(context)` (in `notice_list_screen.dart`) is the horizontal padding every screen body and the preview's bottom buttons use — 16 on phones, and on wide screens whatever centers the content at `contentMaxWidth` (720); the bottom tabs stay as they are. Web-only (`kIsWeb`) parts: a "새로고침" AppBar button on the notice list and "내 할 일" (pull-to-refresh doesn't work with a mouse), centered AppBar titles, and the bundled `GowunDodum` font (`assets/fonts/`, SIL OFL 1.1, Regular only, so bold is synthesized); phones keep the system font and their existing look. The debug `AndroidManifest.xml` sets `usesCleartextTraffic` so the emulator can reach the plain-HTTP dev server; the main manifest declares a `VIEW https` `<queries>` entry for `url_launcher` on Android 11+.

## Commands

Backend — run everything from the `notice/` folder (`serve` is a package; modules import each other as `from serve.db import ...`):
```sh
python3 -m pip install -r serve/requirements.txt
python3 -m alembic -c serve/alembic.ini upgrade head   # create/upgrade tables (run before starting the server)
uvicorn serve.main:app --reload                # API + scheduler; docs at /docs
CHECK_INTERVAL_MINUTES=1 ANALYZE_INTERVAL_MINUTES=1 uvicorn serve.main:app   # faster jobs for testing (defaults 240 / 30)
python3 -m serve.analyze [N]                   # analyze latest N posts → DB (upsert) + serve/analysis_results.csv/json for grading (default 10)
python3 -m serve.imagetest <post_key|detail_url>   # image-analysis diagnostics for one notice
python3 -m serve.extract [post_key|detail_url ...] # analyze real notices → DB + JSON (no args = the 5 TEST_NOTICES); unknown MJU boards get registered
python3 -m serve.test_analyze                  # assert-based tests (no pytest installed); DB tests roll back
python3 -m serve.test_tasks                    # notices/tasks API tests via TestClient with Gemini stubbed (tasks.request_breakdown)
python3 -m alembic -c serve/alembic.ini revision --autogenerate -m "..."   # after changing models.py; review the file, then upgrade
```
- PostgreSQL must be running locally (`brew services list`). Default `DATABASE_URL` is `postgresql+psycopg://sitealert:sitealert@localhost:5432/sitealert`.
- Config comes from environment variables; `serve/__init__.py` loads `notice/.env` (python-dotenv) on import without overriding already-exported values. `.env` is gitignored; `.env.example` is the template. Gemini needs `GEMINI_API_KEY` (the server's auto-analysis just logs a warning and skips without it); models are overridable via `GEMINI_MODEL` / `GEMINI_FALLBACK_MODEL` (notice analysis) and `TASK_GEMINI_MODEL` (task breakdown, default = the fallback flash-lite model, because the default model sometimes takes minutes and the user is waiting on the preview).
- Manual testing endpoints: `POST /sites/{id}/check`, `POST /check-all`.
- CORS (for the web app): `main.py` adds `CORSMiddleware`, allowing `http://localhost` / `http://127.0.0.1` on any port (`flutter run -d chrome` picks a random port); deployed web origins go in `CORS_ORIGINS` (comma-separated).
- No login yet: `main.current_user_id()` always returns user 1 (seeded by migration 0003). Swap that one dependency when auth arrives.

Flutter (from `site_alert/`): `flutter run -d chrome` (web; the server must be running), `flutter run` (emulator; for a real phone `flutter run --dart-define=API_BASE_URL=http://<Mac IP>:8000` with `uvicorn serve.main:app --host 0.0.0.0`), `flutter test` (widget tests fake the server with `http/testing.dart` `MockClient`; one test: `flutter test --plain-name "<name>"`), `flutter analyze`.

`serve/analysis_results.*`, `serve/image_test_<key>/` and `serve/extract_results/` are script output, not source.

## Backend architecture

- `models.py` — `Site` (unique `rss_url`), `Post` (unique `(site_id, post_key)`, which replaces `seen.json`), and `PostAnalysis` (one per post; `result` JSONB holds the full `NoticeAnalysis` with evidence, `unclear` JSONB lists unresolved field names). `post_key` is the numeric ID from `/(\d+)/artclView.do` for MJU links, otherwise the full link. `NoticeDeadline` (one row per extracted deadline, unique `(notice_id, deadline_order)`, `deadline_date` null when unknown, `year_corrected` when the code filled the year) and `User` (minimal), `TaskBreakdown` (prompt B result per notice, unique `notice_id`; source of truth for copying), and `Task` (per-user to-dos; `status` is `draft` (created when the preview opens) or `confirmed` (after "저장"), DB check constraint `ck_tasks_status` — the card's `saved` flag and any future planner list must filter `status == 'confirmed'`; `source` is `ai` (evidence copied from the breakdown, required) or `user` (added by the user, no evidence); `deadline_id` is `ON DELETE SET NULL`; `edited_fields` JSONB records which of title/note/scheduled_date the user changed so auto-scheduling doesn't overwrite them; `scheduled_date` is filled by `tasks.reschedule`). `WeeklyReview` (`weekly_reviews`, one memo per `(user_id, week_start)`, `week_start` = that week's Sunday; completion stats are not stored). Deleting a site must delete tasks → task_breakdowns → deadlines → analyses before posts (FK).
- `rss.py` — `fetch_posts` (requests download, feedparser parse, raises `FeedError`), `save_new_posts` (inserts only unseen keys, updates `last_checked_at`), `check_site`, `create_site` (shared by `POST /sites`), and `ensure_post_for_url` (MJU detail URL → registers the board as a site via `BOARD_PATTERN`/`BOARD_NAMES` if needed, and saves the post from the detail page when it's older than the RSS window).
- Baseline rule: on `POST /sites`, the feed is validated and all existing posts are saved with `notified=True` so registering a board doesn't fire a flood of alerts. Only later-detected posts get `notified=False`.
- `scheduler.py` — `BackgroundScheduler` started/stopped in FastAPI `lifespan`, running three independent jobs: `cleanup_drafts` (hourly; `tasks.delete_stale_drafts` removes drafts whose `coalesce(updated_at, created_at)` is older than `DRAFT_TTL` = 24h), `check_all_sites` (isolates per-site failures: rollback + continue) and `analyze_pending` (analyzes up to 20 posts lacking a `PostAnalysis`, newest-detected first, and stops the batch on the first failure so it retries next run). Both use `max_instances=1`, `coalesce=True`, `misfire_grace_time=None` (catch up after Mac sleep). Analysis is a separate job so `/check-all` doesn't block on Gemini.
- Schema is managed by Alembic (`serve/alembic/`, `env.py` reuses `db.DATABASE_URL` and `SQLModel.metadata`). `0001_baseline` represents the tables that previously came from `create_all` (the existing DB was `stamp`ed). There is no `create_all` anymore — a model change needs a migration.
- `detail.py` — scrapes the full notice page (RSS `summary` is only the beginning). Uses ordered selector lists (`CONTENT_SELECTORS`, MJU = `.artclView`), flattens tables to `a | b | c` lines, truncates at 15k chars. `PageDetail.area == ""` means no body selector matched. `download_images` (Referer header, skips <20KB/unsupported MIME, max 5) is shared by `analyze.py` and `imagetest.py`.
- `analyze.py` — Gemini structured output via the `NoticeAnalysis` pydantic schema (multiple `deadlines` as raw `year`/`month`/`day`, `undergrad`, `*_evidence`), `temperature=0`. `save_analysis` is the single write path (scheduler, `analyze.py`, `extract.py`): it runs `resolve_analysis` (year correction = closest year to the publish date when the year is missing; an explicit year before the publish date is kept but marked unclear; unparseable publish date → null + unclear), then upserts `post_analyses` and `notice_deadlines` with `ON CONFLICT`, deleting only surplus deadline orders so deadline ids stay stable. `load_body` falls back to RSS summary when detail scraping fails, and for image-only bodies downloads the images so `analyze_post` sends them with `IMAGE_NOTE`. `run_with_retry(..., models=(MODEL, FALLBACK_MODEL))` retries transient errors (429/5xx) then moves to the next model in `models`. A model that is merely slow, without erroring, is never abandoned; 404 skips straight to fallback; other errors raise. Prompt text lives in `prompts/<version>/notice.txt` and `image_note.txt` (selected by `PROMPT_VERSION`, default `v2`; `v1` belongs to the old schema and no longer works; filled with `str.format`, so literal braces must be doubled); to compare versions, add a new directory rather than editing an old one. `analyze_post` is used by the scheduler; `PROMPT`, `build_prompt`, `IMAGE_NOTE`, `resolve_analysis`, and `run_with_retry` are reused by `imagetest.py` (which does not write to the DB). Run as a script it also writes `analysis_results.csv` (manual O/X grading columns, utf-8-sig for Excel) and `analysis_results.json` (record of model + prompt + results for contest submission).
- `schedule.py` — all auto-scheduling rules in one place. Constants: `TODAY_METHODS` = {선착순} (all tasks today); other apply methods back-schedule, with the last task of each deadline-date group at `BACKWARD_START_DAYS` (3) before the deadline and earlier ones `BACKWARD_STEP_DAYS` (1) apart, past dates clamped to today, and no deadline → null. The function is the pure `plan_dates(apply_method, [(task_id, due)], today)`, and `today_kst()` uses Asia/Seoul. Date math is code-only, never Gemini.
- `reviews.py` — weekly review. `week_range(day)` returns the Sunday–Saturday of any date. `weekly_review` counts as planned the user's confirmed tasks whose `scheduled_date` falls in that week, and as done those of them with `is_done` (regardless of when they were checked). It computes this live, so checking an old task later changes that week's rate. `rate` is null when nothing was planned. It also returns `unfinished` sorted by date, plus the memo. `save_memo` upserts (trimmed, empty → null, max `MEMO_MAX_LENGTH` = 2000, else 400). The endpoints are `GET`/`PUT /reviews/weekly?week=<any date in the week>`; when `week` is omitted, they use this week via `today_kst()`.
- `tasks.py` — "이거 할래". `GET /notices` (main.py) lists all posts as cards with `link`, `analyzed`, summary, apply method, next upcoming deadline, `saved`. `POST /notices/{id}/tasks?regenerate=` → `prepare_tasks` (the preview): 409 if no `PostAnalysis`; if the user already has tasks for the notice (draft or confirmed), returns them without calling Gemini; otherwise copies the `TaskBreakdown` into the user's tasks as `draft`. Concurrent calls for the same user+notice are serialized with `pg_advisory_xact_lock(user_id, notice_id)`: a retry while the first call is still waiting on Gemini blocks, then returns the first call's tasks instead of duplicating them. Prompt B uses models `(TASK_MODEL, MODEL)` (calling prompt B via `request_breakdown` when none exists — `prompts/tasks/<TASK_PROMPT_VERSION>.txt`, schema `BreakdownResult`, numbered `notice_deadlines` as input → `deadline_index`). The response also carries notice title/link, deadlines and apply method with evidence, `unclear`, and `confirmed`, i.e. everything the preview screen shows. `regenerate=true` keeps done/edited/user-added tasks and replaces the rest with new drafts. `POST /notices/{id}/tasks/confirm` ("저장") flips the user's drafts for that notice to `confirmed` (idempotent). `GET /tasks` → `list_confirmed_tasks`: the user's confirmed tasks incl. done ones, sorted by the task's own deadline date/time (no time = end of that day), falling back to the notice's earliest dated deadline (`deadline_from_notice=true`), tasks with neither last. Its items include `scheduled_date`. `task_deadlines` is the shared "which deadline counts for this task" rule (own dated deadline, else the notice's earliest dated one), used by both the list and scheduling. `reschedule(session, user_id, notice_id)` assigns `scheduled_date` to the user's tasks of one notice using the rules in `schedule.py`. It skips done tasks and tasks whose `edited_fields` contains `scheduled_date`, and those don't take a slot. It runs only when the notice's task set changes: draft creation/regenerate in `prepare_tasks`, `confirm_tasks`, `add_task`, and `DELETE /tasks/{id}`. There is no daily job, and tasks saved before this feature stay null until one of those happens. `PATCH /tasks/{id}` edits title/note/scheduled_date/is_done (records `edited_fields`), `POST /notices/{id}/tasks/items` adds a user task (`source=user`, no evidence; `confirmed` if the notice is already confirmed, else `draft`), `DELETE /tasks/{id}` deletes; other users' tasks are 404. `validate_items` drops breakdown items whose evidence is empty or not found in title/body/attachment names (whitespace-insensitive; evidence starting with `(이미지)` is not checked) and logs `[할일분해]` warnings. Upserts via `pg_insert` don't refresh already-loaded ORM objects — re-read with `populate_existing=True` (or `expire_all`) after one; likewise re-query objects after `commit()` before returning them, or they serialize as empty.
